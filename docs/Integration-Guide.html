1. Zendesk Integration

Setup

POST /api/settings
{
  "zendesk_subdomain": "mycompany",
  "zendesk_email": "admin@example.com",
  "zendesk_api_token": "your-api-token"
}

Key Endpoints

EndpointPurpose
GET /api/zendesk/meTest connection
POST /api/zendesk/full-importFull initial import
POST /api/zendesk/incremental-syncDelta sync since last run
POST /api/zendesk/webhookReal-time webhook receiver
GET /api/zendesk/sync-statusCheck sync state
POST /api/zendesk/push/:idPush ticket to Zendesk

Data stored in: zendesk_tickets, zendesk_users, zendesk_orgs, zendesk_comments, zendesk_sync_state

2. Microsoft Entra ID & Graph

Authentication Flow

  • MSAL.js PKCE authorization code flow
  • Scopes: User.Read, User.Read.All, Group.Read.All, Mail.Send
  • Token cached in browser with silent refresh

Graph API Endpoints Used

EndpointPurpose
GET /api/graph/meCurrent user profile
GET /api/graph/usersAll directory users
GET /api/graph/groupsSecurity groups
POST /api/graph/mailSend email via Graph
GET /api/graph/photo/:idUser profile photos

3. Microsoft Teams

Webhook Setup

POST /api/db/teams_webhooks
{
  "data": {
    "name": "ITSM Alerts",
    "webhook_url": "https://outlook.office.com/webhook/...",
    "events": ["incident_created", "sla_breach", "major_incident"],
    "active": true
  }
}

Supported Events

  • incident_created — new incident with P1/P2 severity
  • sla_breach — SLA timer exceeded target
  • major_incident — MIM declared
  • change_approved — change request approved by CAB
  • escalation — ticket escalated

5. Email-to-Ticket

Configuration

  • Whitelist senders: POST /api/db/email_whitelist
  • Configure templates: POST /api/db/email_templates
  • Process inbound: POST /api/email/inbound
  • Rejections logged to: email_rejections collection

6. CMDB Discovery

Ingestion API

POST /api/cmdb/discovery/ingest
{
  "source": "SolarWinds",
  "scan_id": "SCAN-001",
  "assets": [
    { "hostname": "srv-web-01", "ip": "10.0.1.10", "type": "server", "os": "Ubuntu 22.04" }
  ]
}

Discovered assets are matched against existing CIs and either updated or created.

7. WebSocket (Real-Time)

WebSocket server on same port for real-time dashboard updates:

  • Ticket updates pushed to connected clients
  • SLA breach alerts
  • Notification delivery
  • Stats: GET /api/ws/stats
