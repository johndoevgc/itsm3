VGC-ITSM — Authentication, Authorization & Audit
Version 3.20

1. Authentication

Microsoft Entra ID (SSO)

  • MSAL.js 2.x with PKCE authorization code flow
  • Token validation via JWKS endpoint
  • Automatic token refresh with silent acquisition
  • Supported: single-tenant and multi-tenant configurations

Multi-Tenant Authentication (v3.20)

  • ALLOWED_TENANT_IDS — comma-separated list of authorized M365 tenant IDs
  • AUTHORITY_MODE=multi — uses https://login.microsoftonline.com/common authority
  • Token tid (tenant ID) claim validated against allowed list
  • Per-customer Entra app registration via scripts/provision-customer.sh
  • authMiddleware.js — centralized token validation middleware

Local Authentication

  • RETIRED 2026-05-03: The SHA-256 local-admin login (POST /api/auth/local and Bearer local-hash:) is no longer accepted. Both paths return 410/401. All authentication is via Microsoft Entra ID SSO.

4. Audit Trail

  • Every create, update, delete logged to audit_log table
  • Immutable — no delete/update operations on audit records
  • Records: action, collection, record ID, user, timestamp, full details (JSON)
  • Integrity verification: GET /api/audit/verify-integrity
  • Search & analytics: GET /api/audit/analytics
  • Export: GET /api/audit/export

5. Compliance Evidence

Built-in evidence collection for SOC 2, ISO 27001, and internal audits:

  • POST /api/compliance/evidence — collect evidence artifacts
  • GET /api/compliance/evidence?framework=SOC2 — query by framework
  • GET /api/compliance/export — export compliance package
  • Automatic evidence from: change approvals, access reviews, SLA reports, audit logs

6. Data Protection

  • TLS 1.2+ enforced for all connections (Azure App Service)
  • Azure MySQL SSL required (ssl: { rejectUnauthorized: true })
  • Environment variables for all secrets (no hardcoded credentials)
  • Azure Key Vault integration for secret management (v3.20)
  • CORS restricted to configured origins
  • HTTP security headers: X-Content-Type-Options, X-Frame-Options, X-XSS-Protection, Strict-Transport-Security
  • Input validation and JSON sanitization on all endpoints
  • Managed Identity for service-to-service auth (v3.20)

8. Compliance Report (v3.20)

Consolidated compliance reporting across all governance domains:

  • GET /api/compliance/report — exportable report covering PDPA, SLA, AI governance, audit metrics
  • Includes: data retention compliance, DSAR response times, AI budget adherence, SLA achievement rates
  • PDF-ready format for regulatory submission
